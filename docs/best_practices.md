# CasePilot 最佳实践

面向使用者与二次开发者的中文实践指南，覆盖 5 个主题：输入文档写法建议、方法论选择建议、
禅道导入工作流、双模式配置、评测集维护。所有示例命令均可在本仓库离线复现。

## 1. 输入文档写法建议

CasePilot 支持两类输入：中文需求文档（`.md`）与 OpenAPI 3.x（`.yaml` / `.yml` / `.json`）。
解析器做的是"结构启发式提取"，文档结构越清晰，功能点 / 数字边界 / 主流程提取越准，生成用例质量越高。

**中文需求文档（PRD）**：

- 用 Markdown 标题分节：`## 功能清单` / `## 主流程` / `## 优先级` 等小节标题会被识别；
  每个功能点一行，用「- 」列表或独立段落描述（动宾短语最佳，如「支持账号密码登录」）。
- 数字边界写清楚上下界与含义：优先写「密码长度 8-20 位」「连续错误 5 次」「30 分钟」这类
  数字 + 单位 + 语义的表述。比较词（≥ / ≤ / 至少 / 不超过 / 超过）+ 数字的写法会被直接解析为边界约束。
- 主流程写成有序步骤（1. 2. 3. 或「先…再…然后…」），步骤文本会成为场景法用例基本流的来源。
- 异常 / 例外规则单独成句（如「账号被锁定返回提示，30 分钟后自动解锁」），它们会进入异常流与判定表条件。

**OpenAPI 接口文档**：

- 为每个 operation 写 `summary` 或 `operationId`——它们会成为功能点名与用例标题中的具体词。
- 把数值约束写进 schema（`minimum` / `maximum` / `minLength` / `maxLength` / `minItems` / `maxItems`），
  这是边界值用例数值的唯一来源；`example` 中的具体值会被引用进等价类用例的预期结果。
- `required`、枚举 `enum`、复合关键字（`oneOf` / `anyOf` / `allOf`）会进入判定表条件。
- 资源路径按 REST 惯例分组（`/user`、`/store/order`），迭代 4 新增的「接口端点补齐」规则按
  路径首段分组资源，为主流程未覆盖的资源（如 `/user`）自动补场景法 / 边界值专项用例。

**反例（会降低生成质量）**：整段无标点的需求粘贴、边界只写「少量」「若干」、
功能点与规则混在一大段散文里。

## 2. 方法论选择建议

生成器自动打方法论标注（等价类 / 边界值 / 场景法 / 判定表），但人工评审与补充时按下表取舍：

| 方法论 | 适用输入信号 | 典型用例 | 标注示例 |
| --- | --- | --- | --- |
| 等价类 | 有取值范围 / 枚举 / 类型约束的参数 | 有效等价类（合法值）+ 无效等价类（非法值） | 【等价类】用户名长度有效取值 |
| 边界值 | 数字 + 比较词（≥ / ≤ / 长度 / 次数 / 时长） | 边界点 + 两侧相邻值（少 1 / 多 1） | 【边界值】密码长度 8-20 位 |
| 场景法 | 主流程 / 多步骤操作序列 | 基本流（P0）+ 备选流 + 异常流 | 【场景法】宠物生命周期基本流 |
| 判定表 | 多条件组合（锁定规则、优惠叠加） | 条件组合 → 预期结果的规则表用例 | 【判定表】优惠券叠加判定 |

选择原则：

- 一个需求点可以有多条用例、多种方法论，但**每条用例只标一个主方法论**（标注与用例主体一致，
  judge 的「方法论标注合理性」维度会检查这一点）。
- 边界值优先于等价类：凡是出现数字约束，先写边界点 + 两侧相邻值的边界值用例，再补等价类。
- 场景法保 P0 给核心链路（登录主流程、宠物创建→查询→更新→删除），备选 / 异常流 P1-P2。
- 多条件（≥2 个条件影响同一结果）时上判定表，避免用多条等价类穷举组合。

## 3. 禅道导入工作流

端到端流程（详细步骤与人工验证清单见 [zentao_import.md](zentao_import.md)）：

```bash
# 1. 生成禅道导入 Excel（8 列官方导入模板：所属模块/用例标题/前置条件/步骤/预期/优先级/类型/方法论）
casepilot gen -i examples/prd_login.md -o output/prd_login_cases.xlsx

# 2. CLI 内置导入前自动校验（表头 / 必填字段 / 优先级取值），校验结论「可导入」再进禅道
# 3. 禅道 Web → 测试 → 用例 → 导入，选择导出的 xlsx
# 4. 按 docs/zentao_import.md 的人工验证清单抽查：标题、步骤编号、预期结果非空、优先级分布
```

经验：

- 所属模块列使用「输入文档名 / 资源名」层级（如「用户登录模块需求文档/接口验证」），导入前可在
  Excel 里统一改名，避免禅道里模块散乱。
- 优先级映射：P0→1、P1→2、P2→3、P3→4（导出器自动完成），导入后抽查 P0 用例数量是否符合预期。
- 一次导入一个模块对应的 Excel；大文档先 `--emit md` 预览用例表，确认后再导 Excel。

## 4. 双模式配置（真实 API 与离线降级）

LLM 网关自动选择模式，优先级：`openai` → `ollama` → `mock`，全部通过环境变量配置
（密钥只走环境变量，禁止写入任何文件或命令行参数）：

```bash
# 真实 API 模式（OpenAI 兼容接口，支持自定义 base_url / model）
export CASEPILOT_LLM_API_KEY="..."       # Windows PowerShell: $env:CASEPILOT_LLM_API_KEY="..."
export CASEPILOT_LLM_BASE_URL="https://api.openai.com/v1"   # 可选，默认官方地址
export CASEPILOT_LLM_MODEL="gpt-4o-mini"                    # 可选，默认 gpt-4o-mini

# 本地 Ollama 模式（无需 key，适合本机隐私场景）：探测到本地 Ollama 时自动使用
export CASEPILOT_LLM_MODEL="qwen2.5"      # 同一变量覆盖 ollama 模型名（默认 qwen2.5）

# 重试控制（可选）
export CASEPILOT_LLM_MAX_RETRIES=2        # 解析失败自动重试次数（默认 2，非法值回落默认）
```

模式决策与降级行为（无需额外开关，自动生效）：

- 配置了 API key（`CASEPILOT_LLM_API_KEY` 或 `OPENAI_API_KEY`）→ openai 真实调用；
- 无 key 且本地 Ollama 可达（`/models` 探测）→ ollama 本地调用；
- 两者都不满足 → 自动降级 mock，CLI 打印降级原因（「无 API key 且本地 Ollama 不可达…」）；
- 真实模式下 JSON 解析 / 结构校验失败会自动重试（错误信息回灌提示词，≤ `CASEPILOT_LLM_MAX_RETRIES` 次），
  仍失败抛出清晰中文错误——此时可设 `CASEPILOT_LLM_MAX_RETRIES` 加大重试，或去掉 key 走 mock 确定性生成。

经验：

- 求职演示 / 离线环境直接不设 key：mock 确定性规则引擎（同输入同输出），保证演示可复现。
- 真实 LLM 模式下生成质量更丰富，但建议先用 `casepilot eval` 对照 golden 评分再交付，
  避免 LLM 输出的结构性偏差（解析失败会自动重试并降级，CLI 会打印降级原因）。
- CI 只跑 mock 路径（测试不出网、不需要任何 secrets），见 `.github/workflows/ci.yml`。

## 5. 评测集维护

评测体系分两层，职责不同、配合使用：

- `casepilot eval`：对照 `evals/datasets/<输入名>_golden.json` 的 4 维量化评分
  （结构合法率 / 方法论覆盖率 / 边界数值化率 / 基准要素重合度），适合回归与改进驱动。
- `casepilot judge`：LLM-as-a-Judge 逐条评审（完整性 / 方法论标注合理性 / 优先级合理性 / 可执行性），
  适合单批用例的质量把关与改进建议。

维护 golden 基准集的约定：

- 命名固定为 `<输入文件名去掉扩展名>_golden.json`，放在 `evals/datasets/`，
  `casepilot eval -i <输入>` 会自动匹配。
- 每条基准用例带 `note` 字段写设计理由（如「用户名长度约束边界值用例」），
  评审三元组匹配（模块 + 方法论 + 类型）时靠 note 理解缺口归属。
- golden 是**评测基线，只改生成器不改基准**：分数不达预期时，先看 eval 报告的
  差距明细（如「17/19 三元组覆盖，缺口 = 场景法·接口」），定位到生成规则后改进生成器，
  再复跑确认分数回升（迭代 4 的 `/user` 端点补齐即此流程：97.4 → 100.0）。
- 新增输入样例时同步新增 golden（哪怕先 5-10 条），否则 `eval` 会提示找不到基准集并退出，
  无法参与回归。改动生成器后务必三样例全跑：`prd_login` / `prd_boundary` / `openapi_petstore`
  的分数不得回退（CI 中 pytest 会断言此回归）。

```bash
# 一次跑齐三样例评测（脚本可放在 CI 之外的本地验收流程）
casepilot eval -i examples/prd_login.md
casepilot eval -i examples/prd_boundary.md
casepilot eval -i examples/openapi_petstore.yaml
```
