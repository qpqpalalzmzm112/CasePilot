# 面试问答话术（锚点式答题模板）

面试紧张容易卡顿，这份话术给每道题配一个固定结构：

**锚点句（开口第一句，≤25 字，立住论点）→ 展开要点（2~3 个短点，应对追问）→ 量化收尾（一句带数字收束）**

覆盖三组核心话题、共 12 题，锚点句全部口语化，可以直接出声说。数字与 [resume_snippets.md](resume_snippets.md) 的速查表一致，不能改。

---

## 第一组：设计取舍

### Q1：为什么做 CLI 而不是 Web UI？

- **锚点句**：用户是测试工程师，命令行才能嵌进工作流
- **展开要点**：
  - 测试工程师的日常在终端和 IDE 里，CLI 能直接接进脚本和 CI，Web UI 反而多一层来回切换
  - 求职项目贵在讲清取舍：不做 UI，把精力全投在生成质量、评测体系、导出格式这些核心链路上
  - CLI 的产出全是文件和纯文本（gen / eval / judge），面试官一条命令就能复现
- **量化收尾**：砍掉 UI 换来的是 332 项测试、96.13% 覆盖率、3 个样例评测 100.0 的核心链路。

### Q2：双模式 LLM 为什么这样设计？

- **锚点句**：我做了三级降级，没 key 也能跑完整个流程
- **展开要点**：
  - 决策顺序固定：有 API key 走 OpenAI 兼容真实调用 → 无 key 先探测本地 Ollama（500ms 超时）→ 都不可达降级为确定性 mock 规则引擎
  - 每次运行用中文日志明示当前模式，跑在哪条链路上不用猜
  - 求职项目必须可演示：面试官机器上大概率没有 key，降级链路保证演示不翻车
- **量化收尾**：三级降级让 3 个固定样例纯离线生成 27/30/25 条用例，结构合法率 100%。

### Q3：mock 引擎为什么要确定性？

- **锚点句**：mock 必须确定性，评测分数才能复现和回归
- **展开要点**：
  - 同输入同输出，eval 分数才能当回归基线；输出带随机性的话，分数涨跌就说不清是改进还是抖动
  - 规则引擎强制显式方法论标注，保住产品差异化（等价类 / 边界值 / 场景法 / 判定表）
  - 用例内容锚定输入文档的具体词和数值，从源头拒绝模板套话，测试里用 ≥80% 门禁断言兜底
- **量化收尾**：确定性换来 3 个样例评测 100.0 / 100.0 / 100.0，同输入同分数。

### Q4：禅道 Excel 为什么固定 8 列？

- **锚点句**：8 列对齐禅道官方导入模板，一列都不能差
- **展开要点**：
  - 禅道按表头列名和顺序识别导入文件，错一列整表打回，所以列结构写死，并在导出后自动做导入前校验
  - 8 列覆盖用例核心要素（模块 / 标题 / 前置 / 步骤 / 预期 / 优先级 / 类型 / 关键词），关键词列专门保方法论标注
  - 优先级做 P0-P3 到 1-4 的数字映射贴合禅道取值，校验器逐行检查必填字段和取值合法性
- **量化收尾**：8 列固定 + 自动校验，27 条用例的 Excel 表头、必填、优先级取值全过。

## 第二组：LLM 幻觉处理

### Q5：LLM 输出怎么保证结构合法？

- **锚点句**：LLM 输出先过 pydantic 校验，非法直接拒收
- **展开要点**：
  - TestCase 用 pydantic v2 定义：枚举字段（优先级 P0-P3、用例类型、方法论）、必填校验、禁止未知字段
  - 提示词要求输出 JSON 数组，解析后逐条过模型，不合格的不进用例集
  - 结构校验之外还有覆盖维度检查（数量 / 方法论 / 类型 / 标注非空），格式和内容两道闸
- **量化收尾**：3 个样例共 82 条用例全部通过结构校验，结构合法率 100%。

### Q6：解析失败了怎么办？

- **锚点句**：解析失败自动重试，错误信息回灌提示词
- **展开要点**：
  - JSON 解析或结构校验失败就自动重试，把上一次的错误信息写回提示词引导修正
  - 重试次数可配置（`CASEPILOT_LLM_MAX_RETRIES`，默认 2 次）
  - 重试仍失败就抛清晰的中文错误，不静默吞掉、不输出半截结果
- **量化收尾**：默认自动重试 ≤2 次；mock 链路不依赖 LLM 解析，离线 0 次解析失败。

### Q7：为什么把 temperature 设成 0？

- **锚点句**：temperature 设 0，要可复现，不要创意
- **展开要点**：
  - 测试用例生成要稳定，temperature=0 让同输入尽量同输出，方便对比和回归
  - 这个场景不需要发挥创造力，方法论正确、内容锚定输入才是加分项
  - 和 JSON 输出约束、pydantic 校验、失败重试一起组成防幻觉组合拳
- **量化收尾**：三层防线（temperature=0、结构校验、失败重试 ≤2 次），3 样例结构合法率 100%。

### Q8：怎么评测生成质量，而不是拍脑袋说好？

- **锚点句**：我用自建评测框架量化质量，不拍脑袋说好
- **展开要点**：
  - 4 维离线评分：结构合法率、方法论覆盖率、边界数值化率、基准要素重合度，等权平均 ×100
  - 对照人工整理的 golden 基准集评分，口径写在 README 里可复核
  - 评测全离线、确定性，报告落盘 `output/eval_report_*.md`，随时复跑核对
- **量化收尾**：3 个样例评测总分 100.0 / 100.0 / 100.0，4 维全满分。

## 第三组：质量评估

### Q9：4 维评测框架是怎么设计的？

- **锚点句**：四个维度各管一件事，全部可离线算出来
- **展开要点**：
  - 结构合法率管格式、方法论覆盖率管骨架完整、边界数值化率管预期结果不空洞、基准要素重合度管对齐人工基准
  - 重合度按「模块 + 方法论 + 类型」三元组宽松匹配，避免逐字比对太脆
  - golden 基准集每样例 17-19 条人工整理用例，附设计理由，评测可解释
- **量化收尾**：4 维等权平均 × 100，3 个样例（基准 17/18/19 条）全部 100.0。

### Q10：LLM-as-a-Judge 的打分好坏怎么验证？

- **锚点句**：我用好坏两套用例集验证打分区分度
- **展开要点**：
  - 构造坏用例集（6 条：缺预期结果 + 优先级全 P0）对比正常集，看分数方向对不对
  - 双模式沿用 LLM 网关：有 key 走 LLM 评审，无 key 降级可解释规则评分（如「预期结果为空 → 完整性 1 分」）
  - 4 个评审维度：完整性、方法论标注合理性、优先级合理性、可执行性，1-5 分制，报告给引用具体用例标题的建议
- **量化收尾**：好例 4.9 分、坏例 2.0 分，分差 2.9，评分方向正确。

### Q11：覆盖率 96% 是怎么做到的？

- **锚点句**：覆盖率是门禁逼出来的，不是最后补出来的
- **展开要点**：
  - 测试和功能同轮迭代写，CI 里带 `--cov-fail-under=80` 硬门禁，覆盖率掉线就红
  - 覆盖面按风险排：schema 校验、网关模式决策、解析器、mock 确定性、导出列结构、CLI、评测器好坏输入、judge 双模式
  - 不追 100% 虚高：没覆盖的多是难触发的异常分支，把精力放在断言质量上
- **量化收尾**：332 项测试、总覆盖率 96.13%，Python 3.10/3.12 矩阵 CI 全绿。

### Q12：评测驱动改进的具体例子？

- **锚点句**：评测报告点出缺口，我照着补齐了 /user 端点
- **展开要点**：
  - petstore 的 eval 曾停在 97.4，缺口明细点名：基准要素重合度 17/19，/user 端点用例缺失
  - 在 mock 引擎加接口端点补齐规则：按 path 首段分组，未覆盖资源补场景法专项，参数边界缺口补边界值专项
  - 补完回归评测确认，同时守住用例规模不灌水（petstore 30 条）
- **量化收尾**：重合度 17/19 → 19/19，petstore 评测 97.4 → 100.0。

## 出声训练使用说明

话术不是拿来默读的，要练到开口就能说出来。建议按下面的节奏练：

1. **抄锚点句**：把 12 个锚点句抄到卡片（或手机备忘录）上，只抄这一句，这是每题开口的第一句。
2. **遮住要点复述**：看着题目先说锚点句，再用自己的话展开 2~3 个点，最后必须以量化收尾句结束。展开点不用逐字背，记住关键词就行，数字必须说准。
3. **录音回放**：每题录一遍，目标是单题 60~90 秒内说完，检查有没有「嗯、那个」的卡顿，锚点句是不是第一句就说出来了。
4. **随机抽题模拟**：找人从 12 题里随机抽、打乱顺序问，练到不用想结构也能按「锚点句 → 展开 → 数字收尾」走完。答不上来的题回看展开要点，再练一遍。
5. **考前节奏**：面试前一天过一遍 [resume_snippets.md](resume_snippets.md) 的数字速查表；当天早上把 12 个锚点句朗读一遍，上场只记锚点句和数字。

使用提醒：锚点句的作用是防卡壳的「第一句」，不是背全文；展开点允许换成自己的经历和说法，但量化收尾里的数字（332、96.13%、100.0、2.9 等）与实测一致，不许改。
